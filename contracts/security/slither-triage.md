# Slither triage

Reviewed against Slither `0.11.6` on 2026-09-03. The security lane runs the complete configured detector set without `--exclude`. A postprocessor accepts only the exact detector, severity, confidence, function-signature, source-file, and count fingerprints below; a new location in one of the same detector families fails.

| Detector             | Locations                           | Disposition                                                                                                                                                                                                                                                                                                                                                                                                   | Evidence                                                                                                                                                                                                                                                                                       |
| -------------------- | ----------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `reentrancy-balance` | `createGift`, `_claim`              | False positive. Both public entry points acquire OpenZeppelin's storage-backed `nonReentrant` guard before the first token callback. State is updated before the transfer and any failure, reentry attempt, false return, malformed return, or unexpected debit/credit reverts the entire transaction. The before/after reads are deliberately needed to reject fee-on-transfer and other non-exact behavior. | `test_createGift_reentrantCallbackIsBlockedWithoutBreakingOuterTransfer`, `test_claim_reentrantCallbackIsBlockedWithoutBreakingOuterTransfer`, the cross-function cases in `test/audit/AuditReentrancy.t.sol`, every under/over/false/empty-return rollback test, and the solvency invariants. |
| `calls-loop`         | constructor validation, `claimMany` | Accepted bounded external interaction. Constructor input is deployment-controlled. Runtime batching rejects more than `MAX_BATCH = 20`; a failure intentionally rolls back the entire atomic claim batch. Removing these calls would remove asset validation or exact-transfer checks.                                                                                                                        | Constructor validation tests, maximum-batch tests, atomic rollback tests, and native-precompile lane.                                                                                                                                                                                          |
| `timestamp`          | `createGift`, `_claim`              | Intended protocol behavior. Miner/sequencer timestamp tolerance cannot redirect funds and is negligible relative to day-scale unlock dates. The same comparison is the custody rule: creation must be future-dated and only the named recipient can claim at or after `unlockAt`.                                                                                                                             | Boundary tests immediately before and at unlock, recipient authorization tests, and time-advancing invariants.                                                                                                                                                                                 |

These dispositions are scoped to the current non-upgradeable vault. Any change to the guard, transfer order, batch bound, or timestamp semantics invalidates this triage and requires a fresh review.

The exact accepted report contains 11 findings: two `reentrancy-balance` findings, seven `calls-loop` findings, and two `timestamp` findings. `scripts/contracts/check-slither-report.ts` is the executable allowlist.
