No application or contract source was changed, no external configuration was changed, and no transactions were signed or broadcast.

**Findings, ordered by launch impact**

1. **P1 · Publish the intended test configuration.** The public site currently cannot request a wallet transaction. Rebuild the frontend with chain `84532`, writes enabled, mainnet release disabled, the intended browser-safe Sepolia RPC, and the chosen Convex URL. Verify the resulting public build before recording the demonstration. `NEXT_PUBLIC_*` settings are consumed by the build; changing only server runtime configuration is insufficient. The release selection and gates are in [config.ts](/Users/andylower/Documents/sowmorrow/lib/contracts/config.ts:36). Publishing still requires the owner's launch decision.

2. **P1 · Old gifts are impractical to find or claim.** The inbox begins at the latest block and reads only 2,000 blocks per click. It does not populate rows from indexed gift IDs, even when Convex already knows about the gift. Your existing gift's creation block is `46380689`; at the review snapshot it would require about 62 clicks on “Load older gifts.” A time-locked gift will normally be old when someone returns to claim it. An isolated component test confirmed that a known indexed old gift produces zero visible gift checkboxes. Use the recipient index to discover IDs, then verify each gift against the vault. Make the shared gift page a direct route to claiming that gift. See [claim-inbox.tsx](/Users/andylower/Documents/sowmorrow/components/claim-inbox.tsx:157) and [gift-detail.tsx](/Users/andylower/Documents/sowmorrow/components/gift-detail.tsx:249).

3. **P2 · Notes disappear if the page closes before indexing finishes.** After the transaction receipt arrives, the app clears its persisted submission before the note is attached. The plaintext exists only in React state while the app waits for Convex. Refreshing, closing, or switching away can permanently lose that text; the onchain hash cannot restore it. The reproduction confirmed that remounting after transaction success prevents attachment even when the indexed gift then becomes available. Keep a recoverable pending attachment until the backend acknowledges it, with a clear privacy and retention choice. See [gift-widget.tsx](/Users/andylower/Documents/sowmorrow/components/gift-widget.tsx:555), its attachment effect at line 325, and recovery's empty note at line 628.

4. **P2 · A reorg can attach the wrong note to a replacement gift.** Notes are keyed by chain, vault, and gift ID. Orphaning a creation does not invalidate its note, and `gifts:detail` returns that old attachment without checking it against the replacement creation. Two reproductions confirmed both consequences: the new gift receives the old note in its detail response, and attaching the correct new note fails with `NOTE_HASH_MISMATCH`. Bind attachments to the canonical creation and commitment, invalidate orphaned attachments, and verify the displayed text against the onchain hash. See [events.ts](/Users/andylower/Documents/sowmorrow/convex/events.ts:125), [gifts.ts](/Users/andylower/Documents/sowmorrow/convex/gifts.ts:47), and [notes.ts](/Users/andylower/Documents/sowmorrow/convex/notes.ts:54).

5. **P2 · Reorg cleanup stops behind an orphaned page.** `listEventsAboveBlock` takes the newest 500 rows before filtering out orphaned rows. After the first cleanup pass, those same 500 rows fill the next query, which returns an empty result. Older noncanonical events remain in projections while the cursor can rewind. A 501-row reproduction returned zero candidates when one eligible event remained. Paginate through the block index or query canonicality before applying the limit, and finish cleanup before advancing recovery. See [events.ts](/Users/andylower/Documents/sowmorrow/convex/events.ts:317) and [reconciliation.ts](/Users/andylower/Documents/sowmorrow/convex/reconciliation.ts:357).

6. **P2 · Pending transactions survive wallet changes in component state.** Both Plant and Claim load a persisted transaction only when one exists; neither clears the old state when the storage key changes to a wallet with no pending transaction. The disconnect reproduction retained the old recovery panel. A second account can consequently inherit the first account's blocking state, and recovery can clear the wrong storage key. Reset pending and related UI state whenever the chain/vault/account identity changes. See [gift-widget.tsx](/Users/andylower/Documents/sowmorrow/components/gift-widget.tsx:254) and [claim-inbox.tsx](/Users/andylower/Documents/sowmorrow/components/claim-inbox.tsx:405).

7. **P2 · The review can become stale during approval.** The flow revalidates share conversion before approval, but after approval it checks only recipient resolution and time. A reproduction changed the multiplier while approval settled; the gift still submitted with the original raw amount despite now representing a different number of shares. Revalidate conversion and recipient capabilities immediately before the gift transaction. Separately, source inspection found that simulations pass an explicit account while wallet writes omit it. The installed Wagmi implementation then chooses the connector's current account, so switching accounts during the async flow can change the requested signer. Pin the reviewed account at both approval and gift writes and reject account changes. The account-switch signing scenario was not exercised with a real wallet. See [flows.ts](/Users/andylower/Documents/sowmorrow/lib/contracts/flows.ts:280) and [gift-widget.tsx](/Users/andylower/Documents/sowmorrow/components/gift-widget.tsx:420).

8. **P2 · Monitoring currently checks no stocks.** The deployed `catalog:listMonitoredStocks` returned `[]`; the recent daily signals contain only lag readings. The 13 fixture tokens are therefore not receiving solvency checks. The monitor also records completion when token reads fail, reads liability and balance without a shared block snapshot, and provides no notification delivery. Seed the intended monitored assets, require coverage of every asset with liabilities, read a consistent block, and arrange an actionable alert path. Before mainnet, test insolvency and RPC failure alerts explicitly. See [monitor.ts](/Users/andylower/Documents/sowmorrow/convex/monitor.ts:53) and [catalog.ts](/Users/andylower/Documents/sowmorrow/convex/catalog.ts:226).

9. **P2 · The complete release verification is not green.** The native Base lane produced 119 passes, one failure, and 22 skips. `EchidnaHarnessTest.setUp` installs a mock at the B20 factory address; the native runtime correctly rejects overwriting a precompile. Restrict this mock-dependent helper to the reference lane or give it a native-compatible setup. The latest CI is green but does not run the native lane or Echidna. Browser tests also assume a disabled, mirror-free mainnet preview: the normal Sepolia configuration produced 21 failures and 39 passes, all failures asserting preview-only text or controls. Isolate test configuration and add an enabled-wallet flow before treating browser CI as release evidence. See [EchidnaHarness.t.sol](/Users/andylower/Documents/sowmorrow/contracts/test/EchidnaHarness.t.sol:10), [playwright.config.ts](/Users/andylower/Documents/sowmorrow/playwright.config.ts:28), and [ci.yml](/Users/andylower/Documents/sowmorrow/.github/workflows/ci.yml:1).

10. **P2 · The documented deep-reorg repair cannot handle the condition that halts indexing.** Automatic reconciliation halts when no stored checkpoint remains canonical. Manual repair accepts only an exact stored checkpoint/hash, then requires that hash to be canonical. In that condition there is no valid input. The runbook also passes `now` to an action whose validator does not accept it. Provide a separately controlled, verified full replay/recovery procedure and test the documented command. This finding is from code and runbook inspection, not a live reorg. See [indexer.ts](/Users/andylower/Documents/sowmorrow/convex/indexer.ts:192), [reconciliation.ts](/Users/andylower/Documents/sowmorrow/convex/reconciliation.ts:809), and [operator-runbook.md](/Users/andylower/Documents/sowmorrow/docs/operator-runbook.md:86).

**Other setup and product gaps**

- The app has no test-stock faucet action or link, and no explicit explanation that the Sepolia stocks have no value. The fixture faucet is documented only for developers. Give first-time judges a short path to test ETH, test stock, and the right network. The date picker normally begins tomorrow, so prepare an already-unlocked gift or a clearly test-only short-delay demonstration. Do not make judges wait a day to see a claim.
- Notes are public plaintext. An unauthenticated API query returned the existing note, without a wallet connection or waiting for unlock. The UI warns against secrets but describes storage “for the recipient.” Decide whether notes are public, recipient-authenticated, or encrypted, then make the wording and behavior agree. The hash alone does not make a short note private.
- Recipient review shows only an abbreviated address, including for a resolved name. Make the complete checksummed address inspectable before an irreversible gift. An exchange deposit EOA will not trigger the contract-code warning, even though its customer may have no way to call `claim` from that address.
- The deployed Convex environment has no webhook secret or secondary RPC. Polling is working, so the missing webhook is not a custody blocker, but signed CDP delivery and provider failover are not operationally verified. Either configure and test them or document the intended polling-only release. The frontend also has no secondary RPC configured locally.
- Security headers are present on the public site, including HSTS, anti-framing, `nosniff`, and no-referrer. CSP currently restricts framing only; it is not an executable-script policy. No concrete XSS was found in the rendered note path. A restrictive script/connect policy is additional hardening, not a demonstrated exploit fix.

**Contract assessment and mainnet requirements**

The vault is non-upgradeable, uses a reentrancy guard, checks exact vault balance deltas, restricts claims to the stored recipient, bounds atomic batches to 20, and has no owner withdrawal or cancellation path. Creation pausing and stock removal do not disable existing claims. The reference and adversarial suites exercise these properties, including rollback and hostile-token behavior.

Issuer control remains the largest custody risk. Transfer policy changes can freeze gifts; issuer seizure can leave insufficient backing and cause later claimants to lose out after earlier claims consume the remaining tokens. These are already demonstrated in the contract's issuer-control tests. Stock amounts are stored in raw units and their share representation changes with the multiplier. Base documents these multiplier and policy semantics in its [tokenized-stock integration guide](https://docs.base.org/specifications/b20/tokenized-stocks-on-base). A Sepolia fixture test does not validate the production issuer's current policies or future availability.

The mainnet manifest is still pending, with no vault or Safe address. Before accepting real assets, complete the listed bug fixes; review the Safe implementation, signers, threshold, modules, and operating procedure; verify every production stock's sender, receiver, and executor policies; deploy paused; produce and verify the manifest and explorer source; configure a production backend with monitoring and recovery; and complete a small real-asset end-to-end test after explicit authorization. Confirm permitted product use and target jurisdictions with the issuer's applicable terms. Obtain an independent contract review before meaningful value is locked. Mainnet remains behind its explicit release gate.
